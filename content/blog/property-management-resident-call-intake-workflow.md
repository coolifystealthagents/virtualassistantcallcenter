## Define the resident outcome

Every resident call should end with a clear next step. Capture whether the resident needs a repair, access coordination, leasing information, account help, or a status update. Record the property, unit, callback number, and requested outcome before routing the call.

Write the outcome in plain language so the person receiving the task can act without asking the resident to repeat the full story.

## Separate urgent issues from routine requests

Create an approved decision path for flooding, fire, gas concerns, lockouts, safety threats, and other urgent situations. The intake assistant should follow the property's escalation rules and contact the named owner or emergency service when the policy requires it.

Routine maintenance, inspection questions, package notices, and leasing inquiries can use their own queues. Do not label a call urgent merely because the caller is frustrated.

## Capture useful maintenance context

For a maintenance request, record the affected area, observable symptom, when it began, whether the issue is recurring, and any access restriction. Ask only questions that help the maintenance coordinator prioritize and dispatch the request.

Use the [property management maintenance call triage](/content/research/property-management-maintenance-call-triage) pattern to keep the intake focused. If a resident reports a possible safety issue, preserve the exact wording and route it according to the property's documented policy.

## Protect resident information

Keep notes limited to information needed for service. Do not place payment credentials, passwords, or unrelated personal details in a general call record. Limit access by role and define how long operational notes should be retained.

The [Federal Trade Commission small-business cybersecurity guidance](https://www.ftc.gov/business-guidance/small-businesses/cybersecurity) offers an authoritative starting point for access control, authentication, and data-handling practices. Apply the property's own legal and retention requirements before changing a record policy.

## Route with ownership attached

Send each record to a named queue or owner with the requested outcome, urgency, property context, and promised follow-up window. The [inbound customer call workflow](/services/inbound-customer-calls) provides a useful structure for preserving context when a call moves between the answering team and property staff.

Avoid creating an unowned message. If the correct recipient is unavailable, use the approved backup path and document the handoff rather than asking the resident to call again.

## Review the workflow weekly

Measure complete intake records, correct urgency classification, successful routing, callback timeliness, and repeat calls about the same unresolved issue. Review a small sample with property staff and update one rule at a time.

## Put the workflow into practice

Pilot the workflow for one property and one call category. Confirm the required fields, escalation owner, backup path, and follow-up expectation with the property manager before expanding to additional properties.
