# A call queue priority matrix that staff can apply

*October 22, 2026*

Queue priority is usually decided by whoever answers first and by how loudly the caller complains. A matrix replaces that with a shared order that a new assistant can apply on the first day.

## Rank by consequence, then time

Use two questions: what happens if this call waits, and how long can it wait? A safety issue with a short window ranks above a billing question, even if the billing caller is more insistent.

Create a small grid with four levels: immediate, same hour, same day, and scheduled. Define one or two examples for each.

## Name the call types

List the common calls: new enquiry, existing customer issue, delivery, billing, complaint, internal, vendor, and emergency. Place each in the grid.

Where a call type can span levels, use a qualifier. A delivery call is same-day unless it blocks a scheduled installation, which moves it to immediate.

## Protect the emergency definition

An emergency is a narrow category with a named escalation path. If everything becomes urgent, the matrix collapses and the team is back to first-come, first-served.

Review emergency classifications weekly. A pattern of over-classification means the script or the menu is not setting expectations.

## Make the queue visible

The phone system or a shared board should show waiting calls, age, and assigned priority. Staff should not have to guess which call has waited longest.

## Review the exceptions

Look at calls that were reclassified, escalated, or abandoned. Those cases show whether the matrix matches reality and whether staffing covers the priority levels.

A priority matrix is only useful if it is short enough to memorize and specific enough to resolve disagreements.
