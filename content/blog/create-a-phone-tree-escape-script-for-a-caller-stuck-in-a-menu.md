A phone tree is meant to route a caller in seconds, but a menu that loops can turn a simple question into a hang-up. Callers often press zero, wait, and press zero again without reaching a person. An escape script gives the agent and the caller a shared way out of the menu. The script should be short enough to say while the recording is still playing.

## Key takeaways

- Map the real menu options before writing an escape route.
- Tell the caller the exact keys or words that reach a person.
- Treat a repeated menu as a routing failure, not a caller mistake.
- Take the call first and log the menu path after.
- Review failed paths with the person who owns the phone system.

## Map the menu before writing the escape

Load the current menu and walk it the way a caller hears it. Note every option, the key that selects it, and the path that reaches a live agent. Do this on the same phone system the customer uses, not from a diagram in a planning file. A menu that changed last month may still be described the old way in the script.

Check whether zero works from every level or only from the top. Some systems send zero to voicemail, while others repeat the menu. Test the star key and any stated emergency option as well. Write the result in plain steps an agent can read aloud. The escape route is only useful if it matches the system today.

## Give the caller one clear instruction

Use one sentence with one action. "Press zero twice, and if you hear the menu again, stay on the line and I will take your number" is easier to follow than a list of alternatives. Say the instruction slowly and repeat it once. A caller who is already frustrated will not parse a long explanation.

Ask the caller to confirm when the menu changes. A simple "Tell me when you hear a person or a different recording" keeps the agent informed. If the caller reaches a department that cannot help, the agent should be ready to take the call back. The instruction is a bridge, not a handoff.

## Recognize the loop signals

Listen for the same recording, the same hold music, or the same silence repeating. A caller who says "it is back at the start" has already given the clearest signal. Do not ask the caller to keep pressing keys while the loop repeats. Each cycle adds frustration and makes a calm conversation harder.

Watch for the caller who goes quiet after several attempts. Silence can mean the phone is against an ear, the caller is reading the menu, or the caller has given up. Ask a direct question such as "Are you still there, and what do you hear now?" before assuming anything. The agent should keep the caller talking while the route is tested.

## Take the call without blaming the menu

When the caller returns, thank them for staying and take the details yourself. Avoid saying that the menu is broken or that the caller pressed the wrong key. A neutral line such as "Let me take it from here" keeps the focus on the request. The caller does not need a diagnosis of the phone system.

Capture the reason for the call before explaining what happens next. The menu failure may have hidden the real urgency, so ask an open question first. If the caller needs a department the agent cannot reach, use the approved transfer path. Never send the caller back into the same menu to find it.

## Log the menu path that failed

Write down the option the caller chose, the key pressed, and where the call ended up. Include the time and the phone number the caller dialed. A short code such as "menu loop, option two, no agent" is enough for a first record. The log should let a reviewer rebuild the caller's path without listening to the whole call.

Add the caller's device type if it is known, because some menus behave differently on mobile and landline phones. Note whether the caller used a keypad or spoke an option. If the caller reached a voicemail box, record whose box it was. These details turn a complaint into a fixable routing problem.

## Review menu changes with real calls

Review the failed paths each week and group them by menu option. A single option that fails repeatedly may need a different destination or a shorter recording. A menu that fails from every option may need a live answer during busy hours. Bring the pattern to the person who owns the phone system.

Test a menu change with three calls before announcing it to the team. Call from a mobile phone, a landline, and a headset, and note any difference. Update the escape script the same day the menu changes. The [menu routing accuracy guide](/research/call-menu-intent-routing-accuracy) explains how to check whether callers choose the option that matches their need.

An escape script is a small piece of caller respect. It tells the caller that someone is willing to take responsibility for the route. It also gives the business a record of a menu that may be costing calls. Keep the script visible beside the phone and review it whenever the menu changes.
