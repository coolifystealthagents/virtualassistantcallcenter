# Sampling call notes for completeness and actionability

*October 22, 2026*

Call notes are the memory of a phone team. When they are incomplete, the next agent repeats the questions, the customer repeats the story, and the handle time doubles.

This note describes a sampling method for checking the notes, not the calls.

## Define the standard

The standard should name the required fields: caller, verified identity level, reason, reference, action taken, outcome, and next step with an owner and date.

Add a rule for sensitive information: record the verification method, not the sensitive value.

## Sample across queues and shifts

Use a stratified sample by queue, hour, and agent tenure. The morning shift may document differently from the evening shift, and new agents may need a different template.

Include calls that ended without resolution. Those notes are the most likely to be incomplete and the most important to the next person.

## Score the fields and the action

Score each note for presence, accuracy, and actionability. A note can have all the fields and still be useless if the next step is "follow up" with no owner.

Preserve reviewer disagreement and resolve it with the note in front of both reviewers.

## Link to repeat calls

Where the phone system allows, check whether the caller called again within a defined window about the same issue. A repeat call is a signal that the note or the resolution failed.

Do not treat every repeat as an error; some issues genuinely need a second call.

## Report and coach

Report the sample size, the field completeness, the actionability rate, and the repeat-call share. Share patterns with the team and coach individuals privately.

## Limitations

The method measures documentation, not the conversation. A well-written note can still describe a poor call.
