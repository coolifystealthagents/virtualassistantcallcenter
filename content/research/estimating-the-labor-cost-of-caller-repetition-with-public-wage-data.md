# Estimating the labor cost of caller repetition with public wage data

## Question and scope

This review asks how a small team can estimate the labor cost of a caller who has to contact the business more than once about the same issue. The unit is one repeat contact that a trained handler could have avoided. The estimate covers the handler's time and the supervisor time spent on the same case. It does not include lost revenue or damaged reputation.

The review excludes contacts that are genuinely new questions. It also excludes calls that repeat because the customer forgot the answer. The focus is on repetition caused by an incomplete handoff, a missing note, or a broken promise. That distinction keeps the estimate tied to a fixable process.

## Why repetition is a labor problem

A repeat call consumes the same intake steps as the first call. The handler must greet the caller, verify identity, review the history, and ask what happened. Much of that work duplicates the first conversation. The duplication is invisible when each call is measured alone.

The cost grows when the caller asks for a supervisor or when the case has to be re-opened. A second handler may need to read the entire history before helping. The labor adds up across a month even if each repeat call looks short. A process fix can remove the duplication at the source.

## What public wage data provides

The [Bureau of Labor Statistics](https://www.bls.gov/oes/current/oes434051.htm) publishes wage estimates for customer service representatives through its Occupational Employment and Wage Statistics program. The data includes mean and median wages by industry and area. It gives a defensible starting point for the hourly labor rate. The data does not include benefits, tools, or management overhead.

The [Occupational Outlook Handbook](https://www.bls.gov/ooh/office-and-administrative-support/customer-service-representatives.htm) adds context about the work and the typical entry requirements. That context helps a planner decide how much training a repeat-contact fix might require. The wage figure and the task description together support a rough cost model. Neither source measures a specific firm's repeat rate.

## Build the hourly cost carefully

Start with the wage estimate for the role that handles the calls. Add an allowance for payroll taxes and benefits if the firm tracks them. Add the cost of supervision and the tools used to answer calls. The result is a loaded hourly cost, which is higher than the base wage.

State the allowance as an assumption rather than a fact. A small firm may use a different benefits rate than a large one. A contractor may have no benefits cost at all. The estimate should show the base wage and the loading separately so a reader can adjust them.

## Measure the repeat contacts

Count repeat contacts by matching phone numbers, ticket numbers, or case identifiers. A repeat is a contact about the same issue within a defined window, such as fourteen days. Use the same window each month so the trend is comparable. Record the reason for the repeat when the handler can identify it.

Do not count a caller who rings back to add a new detail as a failure. The distinction between an update and a repetition matters. A short note on the reason keeps the count honest. Review a sample of repeats with the handlers before trusting the total.

## Allocate handling time to the repeat

Use the actual talk time and after-call work for each repeat contact. If the phone system records only talk time, add a standard allowance for notes and follow-up. A repeat call often takes longer than a first call because the handler must reconstruct the history. Measure a sample rather than assuming the average.

Include the supervisor time when a repeat escalates. A supervisor who spends ten minutes reviewing a case is part of the cost. Ask the supervisor to record that time for a month. The record turns an invisible cost into a visible one.

## Multiply by the loaded rate

Multiply the total repeat hours by the loaded hourly cost. Present the result as a monthly range, not a single number. Show the low end with the shortest handling time and the high end with the longest. The range reflects the uncertainty in the sample.

Keep the formula visible so the team can test a different assumption. A reader should be able to replace the wage or the handling time and see a new result. That transparency makes the estimate useful in a budget conversation. It also prevents the number from becoming a fixed belief.

## Compare the cost with a process fix

A process fix might be a required callback field, a clearer handoff note, or a script that reads the next step back to the caller. Estimate the time needed to build and train the fix. Compare that one-time cost with the monthly repeat cost. The comparison shows how quickly the fix could pay back.

Do not assume the fix will remove every repeat. Use a conservative reduction, such as one quarter of the repeat contacts. Test the fix on one queue before applying it everywhere. The estimate should support a test, not a guaranteed return.

## Separate labor cost from customer impact

A repeat call costs more than the handler's time. It also signals that the customer did not trust the first answer. That signal may lead to a lost renewal or a poor review. The labor estimate cannot capture those effects, and it should not pretend to.

Report the labor cost as one part of the case for a fix. Pair it with the repeat rate and a sample of customer comments. The combination gives a manager a fuller picture. A labor number alone can make a process change look cheaper than it is.

## Check the estimate against a real month

After the first estimate, compare it with the next month's actual repeat hours. If the estimate was too high, find out which assumption was wrong. If it was too low, look for repeat contacts that the matching method missed. Update the method rather than forcing the old number to fit.

Keep the original estimate and the actuals in the same file. A visible history makes the next estimate better. It also shows whether the process fix changed the pattern. A single month is a check, not a verdict.

Add a short note for any month with an unusual event, such as a system outage or a holiday. That note explains a spike or a dip that would otherwise look like a change in behavior. Compare the month with the same month a year earlier when the data exists. A seasonal comparison is more honest than a month-to-month one.

## Limits of the method

The method depends on the quality of the call records and the repeat matching. A shared phone number or a transferred call can create a false repeat. A caller who uses a different number can hide a real repeat. The count is a lower bound when records are incomplete.

The wage data is a national or regional average, not a firm's actual payroll. The loaded rate is an assumption built on top of that average. The handling time comes from a sample that may not represent every shift. Those limits belong beside the result.

A reader should also know whether the repeat count includes calls that arrived through a different channel. An email that repeats a phone conversation is still a repeat contact, even if it does not appear in the call log. State which channels were included and which were not. That statement prevents a reader from comparing two reports that measured different things.

## A protocol for one team

Choose a fourteen-day repeat window and one call queue. Export the contacts and match them by caller and case. Sample the handling time for twenty repeats and twenty first calls. Add supervisor time where it applies.

Apply the loaded hourly rate and present a monthly range. Choose one process fix and estimate its cost. Run the fix for a month and compare the repeat hours with the baseline. Record the assumptions and the result so the next review starts from evidence.
